## 五、四个技术结论（都带归因）

### 1. 元数据过滤是最大功臣：+15.1pp

- 19/33 → 24/33
- **原因**：142 块里 125 块是院校章程，模板句（"录取分数线""录取规则"）在纯语义检索下挤占政策/分数线块
- **代价**：Q39 因"政策"关键词误路由；"学费"问题被子分类到 policy（实际在 charter）

### 2. rerank 有效但天花板明显：+2 题

- 24/33 → 26/33
- **原因**：救回 2 道"排序失误"类题（答案在候选池但没进 top5）
- **天花板**：漏检 7 道中 4 道是"候选缺失"，rerank 无能为力

### 3. BM25 对口语化提问失效（本周最有价值的发现）

```
Q41「免试是不是不用考试啊」：
  BM25  0/1  ← 用户说"不用考试"，原文写"综合考查"，词面零重合
  向量  1/1  ← 语义匹配成功
```

**推论**：20 条真实提问中 70% 是口语化的 → **BM25 权重不能高**。

### 4. 评估集有系统性覆盖偏差（本周最重要）

```
core 组（按语料编的题）：24/33 = 72.7%
user 组（真实提问）：20 条里只有 1 条能答（5%）
```

**72.7% 是高估的。真实用户问的问题，75% 超出知识库范围。**

## 六、踩的坑（都记进 KNOWN_ISSUES）

| 坑 | 教训 |
|---|---|
| **PowerShell 自动加 UTF-8 BOM** → 139 块变 138 块 | 工具链会悄悄改数据，读写一律用 `utf-8-sig` |
| **脚本被旧版覆盖 3 次** | 拷文件后必须验证版本（`Select-String` 或 hash） |
| **题表 id `Q41` vs 标注 `U20`** | id 必须端到端一致；脚本应加 id 对齐检查 |
| **`BASE.parent.parent` 路径算错** | 多文件脚本一律用显式参数 |
| **`max_tokens=600` 可能截断答案** | 端到端 4/5 的疑似原因 |
| **拒答判定用纯关键词** | LLM 表达变体无法穷举，需正则 + 长度分层 |

## 九、自检回答

> **"冻结之后 W7 做什么，你想清楚了吗？"**

**想清楚了，W7 做三件事，顺序不能变**：

1. **流式输出**（1-2 天）
   现在 6-9 秒的延迟不可接受。SSE 让首字 0.5 秒出现，体感完全不一样。这是**用户体验的临界点**，不做就没人愿意用。

2. **部署上 HK 服务器**（1-2 天）
   现在只能在自己电脑上跑，`localhost:8000`。部署后才能让别人用，才能做可用性测试。

3. **可用性测试 3-5 人**（2 天）
   **这是最重要的一步**——user 组只有 1 条，统计上没意义。真实用户用 20 条真实提问去测，才能知道系统在真实场景到底怎样。

**公开产出放在最后**，因为写文章需要前面三件事的素材。

**不做的事**：不加功能、不调算法、不补语料。**RAG 已经冻结了。**
