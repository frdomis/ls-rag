# 系统架构说明

## 1. 数据预处理环节
- **输入**：专升本官方政策 PDF/Word 文档（如河南省教育考试院发布的报名办法、分数线文件）
- **处理逻辑**：解析文档文本，按段落/语义切分成 200-500 字的片段，标记来源文件名
- **输出**：结构化的 chunk 列表，每个 chunk 包含 `{"text": "片段内容", "source": "来源文件名"}`

## 2. 向量化存储环节
- **输入**：上一步生成的 chunk 列表
- **处理逻辑**：调用 Embedding 模型把每个 chunk 的 text 转成向量，连同元数据存入向量数据库
- **输出**：可检索的向量索引

## 3. 检索环节
- **输入**：用户提问（如“2026 年河南专升本报名时间？”）
- **处理逻辑**：把用户问题转成向量，在向量库里做相似度匹配，取 top5 最相关的 chunk
- **输出**：5 个和提问最相关的政策片段

## 4. Prompt 组装环节
- **输入**：用户问题 + 检索到的 5 个 chunk
- **处理逻辑**：构造 system_message（约束模型只根据资料回答）和 user_message（包含资料和问题）
- **输出**：符合 OpenAI API 格式的 messages 列表

## 5. 模型调用环节
- **输入**：messages 列表
- **处理逻辑**：调用 DeepSeek API，temperature=0.3 保证回答稳定性
- **输出**：最终给用户的文本回答
