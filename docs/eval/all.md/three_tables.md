**结论：混合检索未带来收益。** 最优配置仅追平 BM25，RRF 反而下降 5.7pp（≈2题量级）。
逐题对照：仅在 Q25「医学类是不是完全不能跨专业」上出现部分互补（双路皆错 → 0.5分），且仅为"偏"而非"对"。

**公平性控制：** 两路均先取 CAND_K=30 再截 Top-5，避免"候选池变大"带来的虚假提升；RRF 与加权融合共用同一候选池。

**已知口径问题（必须在报告里声明）：**
1. 本组分母为 35，与 W3D4/D5 的 17 题不可比（题集更换 + 判定从自动抽词改为标注 keypoints），历史数字已作废，报告只保留本组。
2. `judge_one` 存在假阳性：total==0 时仅凭文件名命中即判"对"，导致"对22 > 内容级20"的矛盾。修正后 BM25 预计降至 ~54%。**该 bug 不影响排序结论（所有配置同口径），但绝对值需重跑修正。**

## 表二：提升点表（错误归因，按修复性价比排序）

| # | 归因 | 现象证据 | 影响面 | 修复动作 | 预期收益 | 成本 |
|---|---|---|---|---|---|---|
| 1 | **语料切分粒度过粗**（答案段落未被切进候选池） | 内容级命中仅 20/40，即检索完美理论上限也远低于 100%；人工核对原文发现要点落在 chunk 边界外 | 高（全局） | 按标题/条款号递归切分，目标 chunk 数 72→200+，重叠 10% | 最高（唯一能突破上限的动作） | 中（需重做入库+重标） |
| 2 | **prompt 未强制引用式作答** | 要点在上下文中但回答绕开/泛化 | 待回答质量轴确认 | 指令改为"逐条引用原文句子作答，无依据则说明不知道" | 高 | 低（改 prompt 即可） |
| 3 | **拒答策略缺失** | 3~4 题超范围（广东、预测分数）无专门处理 | 中 | 前置路由：省份/年份/预测类直接拒答 | 中（提升可信度而非 Recall） | 低 |
| 4 | **要点标注缺失** | 2 题 total==0，判分失真 | 中 | 补全 40 题 expected_keypoints（原子化≤20字） | 中（指标可信度） | 中（人工） |
| 5 | 融合权重 | RRF 负向，加权单调不增 | 低（已证伪） | **停止投入**，固定为纯 BM25 | 0 | 0 |

**一句话归因：瓶颈在语料切分和生成侧，不在检索模型选型。**

## 表三：成本表（每千次问答，估算值，需以实际账单校准）

| 环节 | 单次用量（估） | 单价（估） | 单次成本 | **每千次成本** | 备注 |
|---|---|---|---|---|---|
| BM25 检索 | 本地 CPU，72 chunks | 0 | 0 | **¥0** | 内存索引，<5ms |
| 向量检索 | 1 次 embedding，~40 tokens | bge-m3 ≈ ¥0.0007/1K tokens | ¥0.00003 | ¥0.03 | 可忽略，但增加 ~80ms 延迟 |
| Embedding 缓存命中 | — | 0 | 0 | ¥0 | 同问复用可再省 |
| LLM 生成（输入） | context ≈ 5 chunks × 300字 ≈ 2000 tokens | Qwen3-32B ≈ ¥0.002/1K | ¥0.004 | ¥4.0 | 占大头，随 TopK 线性涨 |
| LLM 生成（输出） | ≈ 300字 ≈ 400 tokens | ≈ ¥0.008/1K | ¥0.0032 | ¥3.2 | |
| **合计（BM25路线）** | | | ≈¥0.007 | **≈¥7/千次** | 不含缓存 |
| **合计（混合路线）** | 两次召回 + 融合 | | ≈¥0.007 | **≈¥7/千次** | 召回成本不变（离线向量已入库），仅增 CPU 融合 <1ms |

**成本结论：**
- 混合检索**没有增加金钱成本**（两路候选均为离线预计算，融合为纯 CPU 排名运算），但带来了**代码复杂度与维护成本**，且收益为负 → 双重理由放弃。
- 当前架构下真正的成本杠杆是 **TopK 大小 × 输出长度**，而非检索路数。若要把 Recall@5 提到 Recall@10，LLM 输入成本翻倍，需用"重排器只喂 top3"来对冲。
- 若要压到 ¥1/千次以下：换更小模型（Qwen3-8B 约 1/3 价格）+ 输出长度限制 + 常见问题缓存，命中率损失待实测。
