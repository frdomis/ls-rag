## 五、关键发现

### 1. user 组样本过小，只能作趋势参考

- **1 条**（Q41）不足以代表真实提问的整体表现
- 向量 1/1、BM25 0/1 **不能推断为"向量对真实提问 100% 有效"**
- **诚实表述**：真实提问在评估集中仅 1 条可测，其余 19 条超出知识库能力

### 2. BM25 vs 向量在真实提问上的差异（最有价值）

**Q41 的具体表现**：

| 方法 | 结果 | 原因 |
|---|---|---|
| BM25 | **0/1** | 用户说"不用考试"，原文写"综合考查"——**词面完全不重合** |
| 向量 | 1/1 | 语义理解"免试/综合考查"的关系 |

**推论**：口语化提问（20 条中 70%）对**词面匹配**极不友好。
**线上影响**：若 BM25 权重过高（如 `w(0.7, 0.3)`），对真实用户会失效。

### 3. 评估集的覆盖偏差已被量化

| 数据 | 数值 |
|---|---|
| 自编题（core）召回 | 20/33 = 60.6%（不过滤）/ 24/33 = 72.7%（过滤） |
| 真实提问可答率 | **1/20 = 5%** |
| 真实提问超范围 | 15/20 = 75% |
| 真实提问部分可答 | 4/20 = 20% |

**结论**：
> **core 组的 72.7% 不能代表真实场景表现。** 真实用户提问中，75% 超出知识库范围，20% 只能部分回答，只有 5% 能完整回答。

## 六、自检回答

> **"core 和 user 的差距有多大？差距说明了什么？"**

**差距**：
- core：20/33 = 60.6%（向量不过滤）
- user：1/1 = 100%（样本仅 1 条，不可比）

**表面上看 user 更高，但这是假象**——因为只有 1 条能进入 user 组。

**真正的差距在于"能进入评估集的真实提问数量"**：
- core：33 条可答（100% 的设计题都在语料范围内）
- user：1 条可答 / 20 条采集（**5%**）

**说明**：
1. **原评估集存在系统性覆盖偏差**——所有题都是按语料编的，天然在覆盖范围内
2. **真实用户问的问题，绝大多数（75%）系统答不了**
3. **因此 72.7% 的召回率是"高估"的**，真实场景下的可用性远低于此

**这正是建立拒答指标和明确产品边界的原因。**
