本项目评估的唯一口径来源。有疑问以本文为准。 最后更新：2026-10-13

1. 唯一脚本
只有 docs/eval/eval_hybrid.py 是正式评估入口（已归档其他 eval_*.py 到 docs/eval/archive/）。
运行：python docs/eval/eval_hybrid.py

2. 分母
评估集题数 = 40 题
拒答题 = 3 题（Q12/Q35/Q40，超范围）
语料缺失题 = 4 题（Q13/Q29/Q32/Q34，库里无答案）
分母 M = 可答题数 = 40 − 3 − 4 = 33

要点总数（评估集）= 128 个
语料可支撑要点 = 82 个（剔除 36 个语料缺失要点）
要点覆盖率 = 覆盖要点数 / 82

recall@5 = 命中 N / 33

3. 命中与拒答
命中判定： 每个 keyword 在回答中做子串匹配，命中 +1。
拒答关键词： 未找到相关信息 / 没有相关信息 / 无法回答 / 资料中未找到 / 资料中暂无 / 暂未找到 / 抱歉 / 参考资料中未 / 提供的参考资料中未
拒答题跳过命中统计，单独计 reject_count。

4. 输出格式
终端唯一汇总行（每次运行只出现一次）：
===== 评估汇总 =====
命中 N / 分母 M = P%
拒答数: R
总耗时: T.s  平均: A.s/题
详细结果 -> docs/eval/report.json
文件输出：docs/eval/report.json（每次覆盖），含 summary + results 两个顶层字段。

5. 清理旧数字
代码/日志/commit message 中禁止出现：14/20、14/18、0%（历史结果）、35.3%。
引用历史数据格式：历史评估（2026-10-XX）：命中 N / 分母 M = P%（见 docs/eval/report.json）

6. 每配置一行
一次运行 = 一组配置，终端只输出一个汇总块。对比实验分两次跑，分别记录。

7. 一致性验证
数据源：docs/chunks/chunks_fixed_v2.jsonl（139 块，id 为 12 位 hex）
向量集合：Qdrant `chunks`（139 点 / 1024 维 / point_id=UUID / payload 带 chunk_id）
验证：python hybrid_compare.py --limit 5 --vector qdrant
通过标准：两路 id 命中文件都是 5/5，且平均排序交集 > 0（2026-10-22 实测 25/25，交集 0.2/5）
未通过 → 检查集合名是否统一为 chunks、payload 是否有 chunk_id

8. eval.py 逻辑速查
流程： 加载 questions.jsonl → 逐题调 answer() → 判断拒答/命中 → 写 report.json → 打印汇总行
关键函数：
函数	作用
is_rejected(ans)	检查拒答关键词
score(ans, keypoints)	关键词子串匹配
parse_chunks(chunks_text)	解析 chunk 文本
main()	主循环
